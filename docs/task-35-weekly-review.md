# Task 35: Weekly Review and Plan Adjustment

The review covers the most recently completed product week: Monday 00:00 through the following Monday 00:00 in `Asia/Ho_Chi_Minh`. It counts submitted learner practice and completed Listening mocks, excludes diagnostic/demo/challenge activity, and reads answered questions from submitted sessions. Empty weeks show a gentle no-data state. Accuracy is shown only when at least one answer exists. Part, skill, and subskill breakdowns require eight answers per group, matching the supported diagnosis threshold. A week comparison requires at least eight answers in each week.

The additive `weekly_plan_snapshots` table records the first plan shown for each user and week. Its unique `(user_id, week_start)` key keeps activity order stable across dashboard requests. The plan is replaced only when the goal's target, exam date, study minutes, study days, or effective Free/Premium plan changes. Quota and content readiness continue to update CTA availability; submitted sessions update completion. No historical plan is reconstructed before the first saved snapshot. This avoids claiming an invented completion rate for older weeks. No backfill, environment variable, or service is required.

At the product week boundary, the next plan uses the completed week's activity and supported weak areas to prioritize repeated mistake review, continued weakness practice, or an unfinished activity. It never raises the number of slots or minutes because of low activity. Mastered mistakes cease to generate review activity when no unresolved mistakes remain. Mock activities still require readiness and entitlement. All actions retain the existing server-side eligibility and quota checks.

The Free review shows actual learning days, completed sessions, questions, accuracy, completed activity types, and up to two focus suggestions. Premium adds evidence-qualified Part/skill/subskill breakdown, current repeated mistake patterns, saved-plan completion, comparison when both weeks have enough answers, and plan adjustment reasons. Neither tier shows predicted scores or readiness estimates.

QA uses the isolated `toeicgym_task17` PostgreSQL database through `ssh english-vps` port 15433. `scripts/task26b-qa-seed.mjs` and `scripts/task35-qa-seed.mjs` write only to that guarded database. `playwright.task35.config.ts` runs the authenticated responsive check on a local app. Production verification uses read-only checks and no QA seed.
